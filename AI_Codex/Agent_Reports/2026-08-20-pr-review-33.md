## Detail

**[2] was a regression against an accepted specification.** `tech-spec.md`
fixes `read_manifests -> list[dict[str, Any]]` and
`manifest_by_name -> dict[str, dict[str, Any]]`, and states the wrappers
"SHOULD log or otherwise expose diagnostics without changing their return
shape". Commit `a83c088` changed both to return `CapabilityManifest`. Nothing
outside the package called them, so nothing was broken in-repo, but the
declared compatibility contract was violated. The wrappers now project
`manifest.wire`; `discovered_capabilities` and `capabilities_by_name` carry the
parsed contracts, and the engine uses the latter.

**[3] reproduced exactly as reported.** `dict.get` collapses an absent key and
an explicit JSON null, so `"type": null` parsed as `AnyType` at the schema
root, on a property, and inside `additionalProperties` — the malformed
capability was accepted and projected to MCP clients. `_parse_type` now takes an
`_Absent` sentinel for a missing key, so a present null is rejected with the
appropriate diagnostic while an absent key stays unconstrained.
