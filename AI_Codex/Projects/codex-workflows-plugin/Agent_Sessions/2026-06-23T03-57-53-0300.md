# Agent Session Log

## Intent

Debug why the plugin was not showing skills in Claude when used through the Antigravity IDE.

## Root Causes Found

### 1 — Plugin not registered with Claude Code

The bootstrap installed the runtime to `~/.codex-workflows/` but never added the plugin to
`~/.claude/plugins/installed_plugins.json`. Claude Code loads plugins (and their skills) from
that registry. Without an entry there, the plugin could not appear in the skills list.

Additionally, when the entry was first added, `installPath` pointed to `~/.codex-workflows/`
(outside Claude's cache). Claude only loads skills from plugins whose `installPath` is under
`~/.claude/plugins/cache/` — matching the structure used by all marketplace plugins.

### 2 — Hook accumulation on each bootstrap run

`merge_hook_configs` in `merge.py` appended hook-group lists unconditionally. Every bootstrap
run added a new hook entry instead of replacing the previous one. The Antigravity IDE's
`.agents/hooks.json` had accumulated 7 entries, including one pointing to a deleted `/tmp/…`
path.

## Changes Made

### `scripts/installer/merge.py`
- Added `_is_hook_group_list` and `_merge_hook_group_lists` helpers.
- `deep_merge` now deduplicates hook-group lists (arrays whose elements have a `"hooks"` key)
  by command string instead of concatenating them.

### `scripts/installer/bootstrap.py`
- Added `strip_managed_hooks(config, script_names)`: strips all hook entries whose command
  references any of this plugin's known hook scripts before merging. Runs on every global wire
  step so stale entries from previous installs are removed.
- Rewrote `register_claude_plugin(install_dir)`:
  - Copies `skills/` into `~/.claude/plugins/cache/local/codex-workflows-plugin/<version>/`.
  - Writes a minimal `plugin.json` there (name, description, version, author only — matching
    the format used by marketplace plugins like azure and stitch).
  - Adds/updates `codex-workflows-plugin@local` in `installed_plugins.json` with `installPath`
    pointing into the cache directory.
- `register_claude_plugin` is now called unconditionally in `main()` after every install step.

### `README.md`
- Installation section updated: Step 1 explains the two things bootstrap does (runtime install
  + Claude plugin registration). Added restart-session note. Updated test count to 91.
  Replaced hardcoded version strings with `<version>` placeholders. Added idempotency note
  to Step 2.

### `CHANGELOG.md`
- Added `[Unreleased]` entries for the hook deduplication fix and the Claude plugin
  registration feature.

## Outcome

- `~/.claude/plugins/cache/local/codex-workflows-plugin/0.2.7/` created with clean structure.
- `codex-workflows-plugin@local` registered in `installed_plugins.json`.
- `~/Antigravity_IDE/.agents/hooks.json` cleaned from 7 stale entries down to 1.
- 91 tests passing.
- Plugin skills visible in Claude after session restart.
