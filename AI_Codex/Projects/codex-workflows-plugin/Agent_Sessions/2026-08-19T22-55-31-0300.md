## Findings in Scope

- `handle_task_completed` promotes dependency-less BLOCKED tasks to READY on any
  unrelated completion.
- `_validate_schema` raises `TypeError` on the JSON Schema `type` array form,
  taking down discovery instead of isolating one manifest.
- `_validate_schema` rejects the subschema form of `additionalProperties` and
  silently drops the capability.
- The engine injects `attempt` into user `arguments`, colliding with strict
  argument validation.
- `_stall_signature` strips volatile fields at the top level only, while
  handlers nest `reflection.attempt`.
- The halt branch of `run_tool_call` discards an interactive approval and
  returns a contradictory `ok=False, state="Ready"`.

## Design Decision

The wire format stays JSON Schema because `input_schema` is passed verbatim to
MCP clients as `inputSchema`. The single unambiguous contract is internal:
raw JSON is parsed once into frozen algebraic types, and no consumer inspects
raw schema shapes afterward. JSON Schema boolean `additionalProperties` is sugar
for the two degenerate schemas and is normalized away at the parse boundary.

## Explicitly Preserved

- MCP `inputSchema` projection and instruction-only prompt behavior.
- Critique-to-prompt feedback and reflection payloads.
- Legacy semantic evaluator default and existing handler compatibility.
- Host adapters, hook runtime, installer, and ticket workflow policy.
